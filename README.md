# 出貨小幫手 V6(Cloudflare Pages 版)

LINE 禮物訂單分類、廠商試算表自動上傳、物流對單、問題訂單、包裹退貨、分區列印。

---

## 架構

```
瀏覽器 ──► Cloudflare Pages(這個 repo)
              ├─ 靜態前端 index.html + *.js
              └─ functions/api.js  ← 唯一的後端入口 /api
                    ├─ 填包貨字卡 ──────────► D1「niyan-db」platform_orders(直接寫,很快)
                    ├─ 問題訂單 ────────────► D1「niyan-db」shipping_problems(直接寫,很快)
                    └─ 寫 Google 試算表 ────► Apps Script(Code.gs)──► 同事看的那幾張試算表
```

搬家前是「前端(GitHub Pages)→ Apps Script → 試算表 + 包貨系統」,
搬家後把「填包貨字卡」這段從 Apps Script 拿掉,改由 Cloudflare 直接寫 D1,
少一趟跨專案往返,上傳明顯變快。**寫試算表的部分完全沒動,同事那邊無感。**

| 東西 | 放哪 |
|---|---|
| 前端 + Pages Function | 這個 repo,推 `main` 自動部署 |
| D1 資料庫 `niyan-db` | `wrangler.toml` 的 `[[d1_databases]]`,Pages Git 部署會自動綁,不用去後台設定 |
| Apps Script `/exec` 網址 | Cloudflare Pages 專案的環境變數 `GS_URL`(沒設就用 `functions/api.js` 裡的預設值) |
| 各試算表「點字卡開啟」的網址 | 寫死在 `sheet-sync.js` 的 `SHEET_URLS`,不再開放設定 |
| 深色/淺色偏好 | 瀏覽器 `localStorage`(`niyan_theme`,⚙ 設定裡切換) |
| Logo | 內嵌在 `index.html` 的 SVG(從 `LOGO.png` 描出來的向量版),漸層吃 `--logo-1`/`--logo-2` 兩個變數。扳手是 `fill-rule="evenodd"` 的鏤空,所以深淺兩種模式都不用換圖。`LOGO.png` 留著當原始素材,頁面已經沒在用了 |
| 試算表 ID | `Code.gs` 裡的 `SHEETS` |

## 後端動作一覽(`POST /api`)

| action | 誰處理 | 做什麼 |
|---|---|---|
| `uploadLineRegular` | Cloudflare(D1) | 一般訂單筆數累加進包貨系統當天「Line禮物(黑貓)」平台字卡 |
| `append` | Apps Script + Cloudflare | 分類訂單寫進廠商試算表;離島那批再累加進「離島•郵局(郵局)」字卡 |
| `addProblem` / `getProblems` / `removeProblem` | Cloudflare(D1) | 問題訂單(`shipping_problems`),2026-09-17 起不再用試算表 |
| `addReturn` / `getReturns` / `removeReturn` | Apps Script | 包裹退貨試算表 |

包貨字卡一律是**累加**不是覆蓋(同一天同平台已有紀錄就把件數加上去),
所以同一天上傳多次不會把包貨系統手動送出的數字蓋掉。

> **不要把包貨同步加回 `Code.gs`。** 若 Apps Script 自己也同步一次,同一批件數會被灌兩次。
> `functions/api.js` 會偵測 Apps Script 回傳裡有沒有 `packingSync`,有的話就跳過自己這次同步
> (這是為了 Apps Script 還沒換成 v6 的過渡期,不是讓兩邊並存的設計)。

## 分區列印:黑貓託運單 PDF 分頁

舊流程是「每組下載一份黑貓出貨表 xlsx → 一份一份丟進黑貓系統」,很花時間。
新流程可以改成:

1. 出貨單產生分頁一次倒出全部訂單 → 丟進黑貓系統
2. 黑貓吐回一份含全部託運單的 PDF
3. 把那份 PDF 丟進分區列印的「黑貓託運單 PDF」欄位
4. 清單上每一組會多一顆「⬇ 託運單」,或按「▶ 全部下載託運單(每組一檔)」一次全出

對應方式是每頁託運單上印的 18 碼訂單編號,跟當天的 LINE 訂單總表比對。
頁序照該組的撿貨順序排,撿貨人拿到的一疊就是那一組的單。

**LINE 訂單總表和託運單 PDF 兩個都要選**才會分組 —— 分組規則(商品編號、別名、
尺寸、雷雕歸類…)全部來自訂單總表,PDF 上只有訂單編號。只選其中一個時,
畫面會直接說還缺哪一個,不會產生半套的結果。

> 曾經做過「只靠託運單備註欄分組、不用訂單總表」的版本,但備註欄的文字
> 抓得不夠穩,分出來的組跟有總表時對不起來,所以移除了。要再做的話,
> git 記錄裡有(commit a0ee69c、300ec88)。

沒被分區清單吃到的頁不會消失,會另外歸類成獨立的檔:

| 情況 | 產生的檔 |
|---|---|
| 訂單表裡有,但分區排除(黑熊/盆景公仔組/離島) | 依類別各一檔,例如 `託運單_黑熊.pdf` |
| 訂單表裡找不到,或抓不到訂單編號 | `託運單_未對應.pdf` |
| 訂單表裡有、PDF 裡卻沒有託運單 | 不會產生檔,改在狀態列提示「⚠ N 筆訂單找不到對應的託運單」 |

原本每組下載 xlsx 的按鈕沒有拿掉,兩條路並存。

`pdf.js`(讀文字)和 `pdf-lib`(重組頁面)都是**用到才載**,沒要分 PDF 的人不會付那 1.9MB 的載入成本。

## 部署

### A. Cloudflare Pages

1. 把這個 repo 推到 GitHub。
2. Cloudflare Pages → Create project → Connect to Git → 選這個 repo
   - Framework preset:**None**
   - Build command:**留空**
   - Build output directory:**留空**(用 `wrangler.toml` 的 `pages_build_output_dir = "."`)
3. 專案建好後到 Settings → Environment variables 新增 `GS_URL` = Apps Script 的 `/exec` 網址。

### B. Apps Script(只負責寫試算表)

1. 把 `Code.gs` 全部貼進原本那個 Apps Script 專案(覆蓋舊的 v5)。
2. 部署 → 管理部署 → 編輯 → 版本選「新版本」→ 部署。
   - 執行身分:**我**
   - 誰可存取:**任何人**
3. 網址若有變,回頭更新 Cloudflare 的 `GS_URL` 環境變數。

### C. 本機測試

```bash
npx wrangler d1 execute niyan-db --local --command 'CREATE TABLE IF NOT EXISTS platform_orders ("id" TEXT PRIMARY KEY,"日期" TEXT,"平台" TEXT,"明細" TEXT,"總件數" INTEGER,"已完成" TEXT,"完成日期" TEXT,"備註" TEXT,"建立時間" TEXT,"更新時間" TEXT,"來源平台" TEXT,"完成物流" TEXT)'
npx wrangler pages dev . --binding GS_URL=<測試用網址>
```

測試時 `GS_URL` 記得指到假的接收端,不要指到正式 Apps Script,否則會真的寫進同事的試算表。

## 試算表欄位

分類試算表(雷雕/黑熊/注意品項/盆景公仔組):

```
日期  姓名  地址  電話  備注  訂單編號  數量
```

永生花(多一欄,由「規格設定」判斷公仔顏色):

```
日期  姓名  地址  電話  備注  訂單編號  黃金數量  粉福數量
```

離島包裹:

```
日期  姓名  地址  電話  備注  訂單編號  數量  離島縣市
```

問題訂單已經不在試算表了,改存 D1 的 `shipping_problems`(欄位見 `schema.sql`)。
「訂單編號」是 UNIQUE —— 同一張單重送是更新那筆,不會產生第二筆。

包裹退貨:同一張工作表裡橫向並排三個平台區塊(line禮物 A 欄起、蝦皮 J 欄起、mo P 欄起),
**不能用整列刪除**,會把旁邊平台的資料錯位。

## 蝦皮出貨(BETA):產生「明細 + 標籤」出貨單

蝦皮的熱感應單上只有收件人和條碼,看不出裡面是什麼,撿貨得另外開裝箱單對。
這個分頁把裝箱單的品項自動縮寫成代號,和原標籤一起排成一張 **95 x 193mm** 的出貨單。

```
┌─────────────────────────┐
│ 胖胖貓(小)黃金*1   胖胖貓(大)綠金*1 │  ← 出貨明細(一欄或兩欄,自動選)
│ 胖胖貓(小)粉福*2   蟾蜍灰*1        │
│                                     │
│ 總金額                        2000  │
│                                     │
│ ←─── 印刷區/分割線,一律留白 ───→   │
│                                     │
│ ┌─────────────────┐ │
│ │   原本的熱感應託運標籤     │ │  ← 整塊向量內容搬過來,條碼/QR 不動
│ └─────────────────┘ │
└─────────────────────────┘
```

1. 把當天全部的檔案**一次拖進同一張卡片**(或按「選擇檔案」):
   每種寄送方式的通通丟進去,`.xlsx` 當裝箱單、`.pdf` 當標籤,自動分
2. 逐頁預覽確認代號和金額,對不到的那幾列會有 ❗
3. 按「產生出貨單」,全部合成**一個** PDF

分批拖是累加不是取代(同名檔案會蓋掉舊的),要重來按「清除」。

蝦皮是每種寄送方式各出一份,所以這裡一次收全部再合成,不用一種一種跑。

### 吃得下的三種來源

蝦皮後台有好幾種下載格式,頁數和順序都不一樣,所以**一律看內容認頁別,不要照位置猜**:

| PDF 裡的頁 | 怎麼處理 |
|---|---|
| 含「撿貨單」 | 跳過,用不到 |
| 含「商品列表」 | 解析成這筆訂單的商品(見下) |
| 其他有「蝦皮訂單編號」的 | 託運標籤,貼到出貨單下半部 |

1. **熱感應寄貨單+裝箱單(A4,一筆兩頁)** ← 現在主要用這個。
   商品就在 PDF 的「商品列表」頁裡,**完全不用另外下載 xlsx**。
2. **熱感應單(A6,一筆一頁)** + 裝箱單 xlsx：PDF 裡沒有商品,要配 xlsx 一起丟。
3. **只有裝箱單 xlsx**(黑貓宅急便,沒有熱感應條碼)。

同一筆訂單如果兩種都有,**以 PDF 自帶的商品列表為準** —— 同事不用再去下載 xlsx。

### 解析「商品列表」的坑

表格欄位是 `# / 主商品貨號 / 商品名稱 / 商品選項貨號 / 商品規格名稱 / 數量 / 總計`。
**不能照文字順序讀**:PDF 的文字是照繪製順序吐出來的,同一條 y 上不同欄位的字會黏成
`1,1200`(#=1、數量=1、總計=200)這種完全看不出來的東西。所以 `parseItemListPage()`
一律**照 x 座標分欄**,欄界是從表頭那一列的各欄 x 位置算出來的(不寫死,蝦皮調版面也還能用)。
商品名稱和規格都會換行,同一欄要把上下好幾行接起來;「買家備註」以下就不是商品了。

**兩種來源的金額欄意思不一樣**:商品列表的「總計」已經是整列小計(直接加),
裝箱單 xlsx 的「價格」是單價(要乘數量)。

**黑貓宅急便沒有熱感應條碼**(標籤是黑貓系統自己印的)。裝箱單裡有、但所有 PDF 都找不到
對應標籤的訂單,下半部改印大字的 `物流單號` + `訂單編號`,上半部的明細/總金額照舊。
版面數字在 `SHOPEE_NOLABEL`。上面還會印「蝦皮黑貓」四個字,跟物流單號一樣大 ——
這張紙上沒有任何條碼,得一眼認出是哪家物流的單。

> PDF 是逐頁抽文字的,幾十頁要跑幾秒。**讀取中按鈕會鎖住** —— 不鎖的話中途按下去,
> 每筆都還對不到標籤,會整份印成「無標籤」而且看起來完全正常,是最難發現的那種錯。

兩邊靠**蝦皮訂單編號**對起來(讀不到才退而用寄件編號:店到家是 `TW`+13 碼,黑貓是純 12 碼)。
對不到的頁會印「查無商品資料」而不是留白,預覽上也會標紅 —— 缺資料要在紙上看得見。

**標籤的裁切範圍 `SHOPEE_SRC_LABEL` 是絕對點數,不是頁面比例** —— 兩種下載格式紙張大小
差很多(A6 / A4),但標籤都畫在同一個絕對位置。`bottom` 抓寬一點(340pt)是因為不同寄送方式的
標籤高度不一樣(店到家 333、標準配送 288),裁多了只是下面多一塊空白,裁少了會切掉條碼。

**版面數字全部照 `蝦皮熱感應輸出範例.pdf` 量的**,寫在 `shopee-label.js` 最上面的
`SHOPEE_PAGE` / `SHOPEE_ITEMS` / `SHOPEE_TOTAL` / `SHOPEE_GAP` / `SHOPEE_LABEL_BOX`。
要調位置改那幾個常數就好,座標一律用「距離頁面上緣」,畫的時候才用 `fromTop()` 換算。

- **一欄還是兩欄是自動選的**:兩種都算一次能用多大的字,取字大的。欄寬只有 93.2pt,
  `胖組合大黃金+木+粉福*1` 這種長代號硬塞進單欄會縮到 6pt,但整張紙明明只有一件商品。
- **總金額** = 每件的「價格 × 數量」加總。裝箱單裡沒有運費欄位,所以這是商品金額。
- **不印發票**:送禮的客人不想讓收禮的人看到價錢 —— 預覽每一列都能勾,勾了那張的金額
  會印成「不印發票」四個字(不是留白,留白撿貨的人會以為漏印)。右上角可以一次全勾。
  勾選狀態存的是**訂單編號**不是頁碼,因為預覽每次都整個重畫,頁碼會跟著檔案順序跑掉。
  畫面上金額還是看得到、只是劃掉,方便內部對帳。
- `SHOPEE_GAP` 那一段程式不會畫任何東西 —— 紙上本來就有印刷,是分割線的位置。

### 代號怎麼來

`[雕][主體(尺寸)][顏色+款式][星座][+加購]*數量`,沒有的整段省略。規則在 `shopee-shortcode.js`。

| 代號 | 意思 |
|---|---|
| `胖胖貓(大)黃金*1` | 胖胖招財招福貓(大)、招財黃、金運,一件 |
| `雕胖胖貓(小對)黃獅子*1` | 雷雕、一對(小)、招財黃、獅子座 |
| `消波4.5+薰衣*1` | 消波塊 4.5cm + 薰衣草精油 |
| `胖胖貓(小)黑金+油組+玫瑰*1` | 胖胖貓(小)、炭錢黑、金運 + 繽紛好運精油組 + 玫瑰天竺葵 |
| `【大小貓組】大黃金+木+粉福*1` | 組合商品,見下 |
| `【繽紛精油組】黃金+玫瑰天竺葵*1` | 依主商品貨號套特例,見下 |

對照字:黃=招財黃、粉=戀愛粉、綠=健康綠、白=純淨白、灰=清水灰、黑=炭錢黑、六=一套六色;
金=金運、福=招福;木=木片底座、寶=元寶、霜=護手霜、油組=繽紛好運精油組。
**精油一律寫全名**(玫瑰天竺葵、薰衣草、佛手柑…),不縮成兩個字 —— 半截的名字在現場容易念錯拿錯。

### 依主商品貨號的特例:`SC_SKU_RULES`

賣場標題三天兩頭改,**貨號不會**,所以能認貨號就別去比對標題。表在 `shopee-shortcode.js`,
每一項都是可選的:`item` 換掉主體名稱、`size` 覆寫尺寸(`""` = 不印)、`style` 固定款式、
`dropAddons` 拿掉多餘的加購字樣。

| 貨號 | 賣場標題 | 代號 | 為什麼 |
|---|---|---|---|
| `niyan_RedGiftBag` | 【送禮首選】繽紛好運精油組 胖胖招財貓 (小)+精油 【交換禮物】 | `【繽紛精油組】黃金+玫瑰天竺葵` | 現場叫「繽紛精油組」;只出金運、顏色買家選、只有一種尺寸所以不印尺寸;品名已經說了是精油組,不用再印「+油組」 |

貨號在兩種來源都拿得到:裝箱單 xlsx 的 `主商品貨號:` 欄、PDF 商品列表的「主商品貨號」欄。

商品標題寫「胖胖招財招福貓」,但現場一律叫**胖胖貓**,代號照現場的叫法。
蝦皮的商品選項有「左手/右手」,經確認撿貨用不到(款式就決定了是哪一隻),只拿來判斷金運/招福,不印。

**組合商品**(`胖胖招財招福貓組(大胖胖金運貓招財黃、小胖胖金運招福貓、原木片)`)括號裡是固定內容物,
買家只能選其中一隻的顏色/款式,所以拆成三段:`胖組合` + 固定那隻(`大黃金`) + 內附小物(`+木`) + 買家選的(`+粉福`)。
固定那隻取括號內用「、」分開的**第一項** —— 它的品名只會出現「金運貓」或「招福貓」其中一個,
第二項是「金運招福貓」兩個都有,不能這樣抓(那隻本來就由買家的規格決定)。

### 手動改文字、拿掉某幾張

預覽每一列都有「編輯」,可以直接改那張要印的文字(一行一個品項),改過的會標 ✎。
自動縮寫是規則產生的,但總有規則想不到的情況(臨時換贈品、客人加註),讓人能直接改
比一直加特例規則實際。**改字不會動到金額** —— 紙上寫什麼和對帳的數字是兩回事。
按「還原」回到自動縮寫。

每一列也有 ✕ 可以把那張拿掉不印(已經印過的、或對不到資料的),右上角有「復原」。
✕ 認的是「哪一份 PDF 的第幾頁」而不是訂單編號 —— 同一張訂單重複下載過兩次時,
用訂單編號會一次砍掉兩頁。另外**過濾要放在 `shopeeBuildJobs()` 的最後一步**,
因為「哪些訂單已經有標籤」必須用全部標籤頁去算,不然 ✕ 掉一張標籤,
那筆訂單會立刻冒出一頁「無標籤」版,等於刪不掉。

### 中文字型:不要改用 pdf-lib 的 subset

PDF 一定要**把字型嵌進檔案裡**才能保證在別台電腦、別台印表機印得出來,不能只寫字型名稱。
中文字型不管哪一套都有兩萬多字、9MB,整包嵌進每張出貨單不切實際,所以要先切。

**但 pdf-lib(@pdf-lib/fontkit)的 `subset: true` 對中文是壞的** —— 會靜靜掉字、不報錯。
實測同一行裡「貓」「大」「右」「粉」印不出來,「黃」「金」卻正常;連已經切成 1.8MB 的
子集再交給它 subset,整行也只剩零星幾個字。**所以產 PDF 時一律 `subset: false`。**

現在的做法:

- `build-shopee-font.py` 離線把 Noto Sans TC Bold 切成 **Big5 常用字(5,401)+ ASCII + 標點**,
  約 1.8MB。切這麼大是因為預覽可以手動改文字 —— 只留代號用字的話,臨時打個「贈品」
  「急件」就會變成「□」。
- 輸出兩個 js:`shopee-code-chars.js`(16KB,字型含有哪些字)隨頁面載入,給預覽判斷缺字用;
  `shopee-code-font.js`(2.4MB base64 字型本體)**選好檔案時才開始載**,載一次就被瀏覽器快取。
  其他四個分頁用不到,沒道理每個人開網站都先拖 2.4MB。
- 用 base64 內嵌而不是 `fetch("*.ttf")`:同事常直接用檔案總管點開 `index.html`(`file://`),
  瀏覽器會擋掉抓同目錄檔案的請求,只回一句「Failed to fetch」;`<script src>` 則不受影響。
- 產出的每份 PDF 會多約 1.2MB 的字型,對列印沒差。
- 真的打到 Big5 以外的字(簡體、日文漢字、emoji)還是會變「□」,存檔時會當場把那些字列出來。

> **改了縮寫規則**:新字加進 `SHOPEE_CODE_CHARS` → 重跑 `python build-shopee-font.py`
> → 三個產出檔(`.ttf` / `.js` / `-chars.js`)都要 commit。

### 其他兩個踩過的坑

- 蝦皮裝箱單的 `<dimension>` 寫成 `A1`(他們產檔的 bug)。SheetJS 會自己重算範圍所以沒事,
  但用 openpyxl 的 `read_only=True` 讀會以為整張表只有一格。換解析器時記得別信 dimension。
- 熱感應單上的訂單編號固定 **14 碼**英數。pdf.js 回傳的文字去掉空白後,編號會跟後面的
  門市代號(`2423…`)黏在一起,所以只能取標籤後面剛好 14 碼 —— 寫成 `{12,20}` 會多吃門市代號。

## 拖曳上傳

**全站每個檔案欄位都可以拖曳**,放置區是該欄位所在的整張卡片(比細長的檔名列好瞄準)。
副檔名不對會擋下來,並在那一頁的狀態列寫清楚只收哪些格式 —— 安靜地什麼都不做的話,
人只會以為系統壞了然後再拖一次。

實作在 `ui-utils.js` 的 `setupDropZone()`,綁定表在 `app-init.js` 的 `DROP_ZONES`。
新增檔案欄位時在那張表加一列就好。兩個和瀏覽器行為有關的細節:

- **`window` 的 `dragover`/`drop` 一定要 `preventDefault`**。瀏覽器預設會「開啟」被丟進來的
  檔案 = 直接離開這一頁,還沒上傳的東西全沒了。只在放置區攔不夠,丟歪一點落在卡片外就中。
- **`dragleave` 要用進出計數**,不能一觸發就移除樣式 —— 游標移到子元素上也會觸發,會一直閃。

拖進來的檔案是直接塞回原本的 `<input type=file>` 再發 `change`,所以載入流程跟用點的完全共用,
不會有兩套。
